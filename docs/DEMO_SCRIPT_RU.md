# Сценарий демонстрации до 3 минут

Записывать итоговую демонстрацию после реального Kaggle-прогона.
Если проверки не пройдены, прямо назвать демонстрацию прототипом.

**0:00–0:20. Задача.** «Мы оптимизируем фиксированное QLoRA-обучение Qwen2.5-1.5B-Instruct
на одной Kaggle T4. Данные, настройки обучения и итоговый адаптер проверяет официальный harness».

**0:20–0:55. Код.** Открыть `solution/kernels.py`. Показать разбиение словаря на блоки по 4096:
каждый блок вычисляет log-sum-exp, затем одна редукция объединяет результат строки.
Backward вычисляет softmax минус целевой класс. Игнорируемые токены дают нулевой градиент.

**0:55–1:20. RMSNorm.** Показать forward/backward. Объяснить, что промежуточные вычисления
идут в float32, а порядок преобразований типов соответствует Qwen. Замороженные веса
нормализации остаются замороженными. Пример SwiGLU взят из starter и не заявляется как наш.

**1:20–2:10. Доказательства.** Открыть сохранённую публичную Kaggle-версию и SHA.
Показать фактические тесты, таблицу официальных проверок и result.json.
Назвать реальное время, пик памяти, loss и долю собственных ядер. Если есть FAIL, назвать его.
Не показывать цифры организаторов как собственный результат.

**2:10–2:40. Ограничения.** Объяснить, что оптимизация cross-entropy не удаляет полные logits:
они нужны остальным метрикам Soup. Результаты относятся к конкретному фиксированному запуску.
Порог 5% и качество проверяются отдельно, ускорение заранее не гарантируется.

**2:40–2:55. Запуск.** Показать ссылки в README и SUBMISSION.md и команду Run All.
Закончить до отметки 3:00.
